# GAME_SPEC: Pembusukan Otak (single source of truth for gameplay)

## 1. Concept

A Brainrot-themed match-3 game. Story Mode: conquer a brain-shaped map (5 areas, outer edge to center, top-down) by matching candies to damage brainrot enemies; the story is about how social media disrupts focus. Time Kill: score attack in 2 minutes with time penalties, bonuses, and power-ups. A Meme Book explains the memes, 5 achievements, a Credits popup with a donation QR, and Settings (music slider, sfx slider, language). English and Indonesian.

Pillars: simple to read, fast fights, meme humor, works on any device, matches the mockups.

## 2. Technical rules

- Phaser (latest stable major version; verify and pin the exact version in Phase 0), Vite, JavaScript ES modules, Vitest. No backend, no runtime network, no analytics, no ads.
- Commands that must work: `npm install`, `npm run dev`, `npm run build`, `npm run preview`, `npm test`, `npm run sync-assets`. `dev` and `build` run `sync-assets` first. The build is a static folder for any static host.
- Folder structure (one job per folder):

```
design/              owner's 7 mockup PNGs (+ optional DESIGN.md). READ-ONLY.
visual/              owner's minion, boss, candy art, any sizes. READ-ONLY.
audio/               owner's bgm and sfx. READ-ONLY.
scripts/             sync-assets.mjs
public/assets/       GENERATED by sync-assets (never edit by hand)
src/
  main.js            only creates the Phaser.Game
  config/            game.config.js, screen.config.js, theme.config.js, gameplay.config.js,
                     enemies.config.js, bosses.config.js, candies.config.js,
                     memebook.config.js, achievements.config.js, audio.config.js,
                     assets.map.js (owner overrides), assets.generated.js (generated)
  i18n/              index.js (t, setLanguage), en.js, id.js, lore.en.js, lore.id.js
  core/              pure logic, NO Phaser imports
    rng.js           seedable RNG (mulberry32): rng.game() for outcomes, rng.cosmetic() for effects
    board/           create, findMatches, resolveMove, hasMove, shuffle, settle, applyPowerUp
    combat/          stats.js (statsForStage), enemy.js (enemyFor), fight.js, bossEffects.js
    timekill/        timekill.js
    progression/     story.js (unlock, replay, Fast Hand tracking)
    unlocks/         memebook.js, achievements.js
    assets/          fit.js (pure size-fitting math)
  scenes/            Boot, Preload, MainMenu, StageSelect, Battle, TimeKill, Results,
                     MemeBook, Achievements, StageClear, GameOver, Tutorial, StoryText
  systems/           LayoutManager, InputManager, AudioManager, SaveManager, EventBus,
                     AssetResolver, PlaceholderArt
  ui/                reusable components: TopBar, Button, Panel, Popup, Gauge, Slider,
                     Toggle, InkText, LocalizedText, SpriteFit, Hud
tests/               mirrors src/core, plus i18n and assets tests
```

- Rules: scenes only wire core logic to visuals; no game rule in a scene or UI file; no number or string literal outside `config/` and `i18n/`; modules talk through `EventBus` or function calls, no globals; target under about 300 lines per file; asset keys come only from the generated manifest.
- Screen: all screen behavior lives in `config/screen.config.js`. Default: Phaser Scale Manager in RESIZE mode plus `LayoutManager` (see `UI_SPEC.md`).
- Input: pointer events only (touch and mouse). Swap by dragging a candy toward a neighbor, or tap one then tap a neighbor.
- Persistence: `localStorage` key `po_save_v1`, every access in try/catch, versioned.
- Assets and audio: see `ASSETS_SPEC.md`. The game must run with zero owner assets (placeholders). A missing asset never crashes.
- Text and language: see `UI_SPEC.md` section 7. All visible text goes through `t(key)`.
- Debug: `?debug=1` multiplies player attack by 10 for faster QA. Controlled by a config flag, off in the production build.

## 5. Rules in detail

### 5.1 Board and moves (`core/board`)
- Grid `grid[r][c] = { type: 0..5, power: null | 'line' | 'bomb' | 'freeze' | 'x5' }`, size `rows x cols` from the mode.
- Starting board: random types, no existing match, at least one valid move, no power-ups.
- A move is a swap of two adjacent candies. Valid only if it creates at least one match; otherwise revert.
- `resolveMove` is pure and deterministic for a given rng. Loop until no matches remain: find runs, clear the union (power-ups in the cleared set trigger once each), gravity, refill from the top. Record steps `{ index, cleared, scoreRaw, longestRun, falls, spawns }`; `index 0` is the player's direct match, `index >= 1` are cascades. After `hardChainCap` steps, call `settle` and stop.
- Return `{ valid: false }` or `{ valid: true, steps, grid }`.

### 5.2 Player stats (Story Mode)

| Stage | HP at start | Attack per candy |
|---|---|---|
| 1 | 100 | 2 |
| 2 | 120 | 3 |
| 3 | 140 | 4 |
| 4 | 160 | 5 |
| 5 | 180 | 6 |

Example: at stage 1, destroying 2 candies deals 4 damage.

### 5.3 Enemies (static in every stage, no scaling)

| Enemy | HP | Damage | Interval |
|---|---|---|---|
| Small minion | 50 | random 2-4 | 15 s |
| Medium minion | 150 | random 2-4 | 15 s |
| Large minion | 200 | random 2-4 | 15 s |
| Boss, stages 1-4 | 250 | 5 + 1 random effect | 10 s |
| Boss, stage 5 | 350 | 5 + 1 random effect | 10 s |

Fight order per stage: small, small, medium, medium, large, then the boss. Fights are 1v1. Each area has its own minion visuals.

### 5.4 Fight loop (`core/combat/fight.js`)
- Each step of a resolved move deals `attack x cleared` damage. If the enemy HP reaches 0, stop the damage, resolve the rest of the board silently, then the enemy is defeated (heal to full, next enemy). Boss defeated: Meme Book boss unlock. Stage 5 boss defeated: story complete.
- Each enemy attack: player HP -= damage; boss attacks also trigger one random effect (cast after any in-flight player move resolves, decision 31) and play that boss's SFX; minion attacks play the hit SFX. Player HP <= 0 is a game over (decision 8).
- Fight logic takes an injected clock, so tests can use a fake clock.

Hidden bonus: Detox Complete (decision 39), shown only once unlocked, counted as a 6th on top of the total of 5.

### 5.10 Balance reference (for the Phase 3 simulation test, not a rule)
Formulas: candies = enemy HP / attack; matches = candies / 3; fight time = matches x 4 s; enemy attacks = floor(fight time / interval); damage taken = attacks x damage (minion average 3). Expected results:

| Stage | Player HP | Worst minion fight (avg damage) | Boss fight damage |
|---|---|---|---|
| 1 | 100 | 24 (large) | 80 |
| 2 | 120 | 15 (large) | 55 |
| 3 | 140 | 12 (large) | 40 |
| 4 | 160 | 9 (large) | 30 |
| 5 | 180 | 6 | 35 |

Boss effects are not included. Do not change any number because of this table; report differences in Known issues.

## 6. Architecture notes
Scene flow: Boot -> Preload -> MainMenu -> (StageSelect -> [StoryText] -> Battle -> StageClear | GameOver) | TimeKill -> Results | MemeBook | Achievements. Popups (Settings, Credits, Donation QR, Pause/Leave, Tutorial) are overlays available where the mockups show them. Battle and TimeKill read the layout from `LayoutManager` and listen to `layout:changed` and `language:changed`. Input is locked unless the scene is in its playable state.

## 7. Out of scope (do not build)
Online features, ads, purchases, multiplayer, leaderboards, native app packaging, extra characters, skins, shop, coins, energy, XP, stars, perks. Extra modes other than Hard mode and Boss Rush (decisions 35, 36, owner request).
